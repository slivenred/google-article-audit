# Specialized article formats

Read only the relevant section; select its module's official guide and verify its current fields. These are conditional Search/feature checks, not a requirement to add schema or change an article's purpose. Distinguish required fields, recommended fields, content policies, product-specific scope and unresolved documentation differences.

## Recipe

Use only for actual preparation of a dish. Check recipe name, representative finished-dish image and real visible ingredients/instructions. Verify claimed time, servings and nutrition rather than inventing them. Per-serving nutrition needs its corresponding serving basis. HowToStep and HowToSection are still used inside Recipe; retirement of standalone HowTo doesn't remove them. Recipe image markup does not control an ordinary text-result thumbnail.

## Discussion forum and Q&A

DiscussionForumPosting/SocialMediaPosting represent genuine user-generated posts and discussion, not a publisher article merely because it permits comments. Preserve the original post, replies, quoted material, full text, timestamps and actual counts. An author avatar isn't the post's inline image. Check current recommended digitalSourceType, comments and format guidance only for the applicable type.

QAPage normally centers on one question with user-submitted alternative answers. The education exception permits a user-submitted homework question answered by in-house experts. It does not make editorial FAQ/essay/how-to content eligible. Check the site's actual accepted-answer mechanism; newest answer does not equal accepted. An unanswered question with answerCount 0 is not rich-result eligible. Do not forge answers or feedback to meet required fields.

## Dataset

Require a real dataset and its landing page/download/provenance, not an article recast as a data artifact. Check current required name/description constraints and actual creator/license/distribution. Use sameAs versus isBasedOn only when unchanged republication versus a derivative is supported. Related-paper citations are not the dataset's identity. Dataset Search discovery is not promised web ranking; lack of DCAT support in Rich Results Test is a validator limit, not proof the dataset is bad.

## Carousel and movie list

Confirm a supported item type and real visible list/destinations. Host carousel supports specific types; arbitrary “best products” lists do not automatically get an ItemList rich result. Check general minimums and any stricter type-specific requirement (Course list differs). For a movie list check actual movie identity, representative accessible image and carousel requirements. Optional review/rating properties need genuine evidence; never invent popularity scores.

## Software application

Verify substantive app information, actual price/offer, OS/category and genuine required review/rating evidence against the current guide. Free download does not imply all functionality is free. Missing required review/rating evidence limits that feature; it does not justify inventing stars or blocking an otherwise sound software article. Apply subtype/co-typing rules only when relevant.

## Education Q&A and course list

Education Q&A targets real educational flashcards, not generic article FAQs. Verify visible question/answer pairs and pedagogical correctness. Check current supported language/region: Chinese was not in the documented list at the 2026-10-08 source read. Do not fabricate curriculum alignment. User-submitted single homework questions route separately to QAPage.

Course list is for a genuine course catalog with the current count/content requirements, not isolated explainers relabeled as courses. Verify real provider, curriculum/outcomes and instructor/student context where applicable. The source read found a discrepancy: technical guidance said every course needs a valid provider, but the property table called provider recommended. Surface the unresolved labeling difference, use real provider information if available, and check current guide/validator rather than inventing a universal rule. Retired Course info is distinct from Course list.

## Web Stories

Apply only to actual Web Stories. Verify valid AMP story, actual publisher/title/poster/logo, canonical/index access and mobile card rendering. Read every card for a complete narrative, rights, truthful media and a delivered conclusion rather than a teaser requiring an external visit for essential facts.

Separate Web Stories policy from design recommendations. At the cached read, the content policy warned about a majority of cards over 180 characters, while design advice mentioned about 280. Do not merge these into a made-up common cap; prioritize applicable policy for feature eligibility and disclose the source tension. Neither number is an ordinary article length rule. No feature or region availability guarantees exposure.

## Paywall sampling

Flexible Sampling discusses metering/lead-ins and experimentation. Its example quotas are recommendations for relevant publishers, not compulsory free-article allowances. Inspect logged-out experience and requested access intent before proposing changes; don't remove subscriptions or change serving behavior during an article audit. Use the separate paywall markup guide for crawler and structured-data checks.

## Retired and unrelated formats

Use current Gallery/update logs to verify retirement. Cached evidence as of 2026-10-08 records FAQ and standalone HowTo retirement; ClaimReview Search results phased out, with a separate Factcheck Explorer product distinction; Course info, Learning video and Practice problem Search features are also retired. These facts don't prohibit useful FAQs, instructions, fact checking, courses or videos. Do not substitute ineligible QAPage or delete useful content to chase markup.

Jobs, events, local businesses, vacation rentals, specialized solver tools and regional product programs require a matching real use case and their own guide. A linked item in Search Gallery is not evidence that it has been audited or should be implemented.
